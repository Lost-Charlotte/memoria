## 一、它解决什么问题

写这套东西的人（AI）有一个致命毛病：**长对话被压缩一次，当天早些时候的细节就全丢了。**
为此建了一套本地档案（`DeepSeek档案`，按 L1~L8 分层）当"抗压缩记忆"。

但档案本身又长出第二个毛病：**一件事要在六七个文件里分别写一遍**（时间轴、事件表正文、事件表的索引表、总览、工具速查、待办、错误总账……），
**只要漏掉一处，档案就开始自相矛盾**——而矛盾会误导下一个接手的人。2026-09-16 一天里，光是"同步漏了"就查出 **28 处**问题。

梅莫莉亚就是冲着这两个毛病去的：**前者靠注入，后者靠体检与闸门。**

## 二、能力总表（**一张表说清她都能干什么**）—— 其中几个是"哨兵"

> ⚠️ **这张表与 `lib/manifest.js` 的清单必须双向一致**（少一个 / 多一个都算漂）—— 有机器检查盯着：
> `node tests/consistency.mjs`。所以**加能力时这张表也要改**，这是硬要求，不是提醒。
>
> 🔀 **2026-09-18 工具合并（10 个 `dangan_*` → 6 个）**：合并的只是**工具面**（模型看到的入口），
> **能力编号与内核一个都没少** —— 被并的能力**不再单独占一行**：它的"能做什么"并进了吸收它的那一条。
> 为什么并：**用户原话〔会话 2026-09-18〕**"**梅莫莉亚现在的工具已经很多了。你看有没有可以合并的。**"
> 并法是按"同一件事"并（都是"读"的并在 `dangan_search`；都是"照某份权威现算并比对"的并在 `dangan_check`），
> 不是为了凑数硬塞。

## 三、全新环境：下载下来就能自己长出一座档案馆（F20）

> 目标（用户 2026-09-17 定的标准）：**这个插件包会被上传，但档案不会被上传。**
> 所以包里**只有代码与骨架** —— 换台机器、换个用户，它必须能**从 0** 建出一座能用的档案馆。

**三步：**

1. **装**（见 §四）→ 重启控制台。
2. **看**：`~/.dsh/memoria/memoria.log` 里会出现一行 F20 自检，直接告诉你现在是什么状态
   （档案根不存在 / 空壳 / 缺哪几件 / 齐全）。**这一步就是"不再静默失效"** ——
   以前档案不在时，入口读不到、铁律找不到、工具全返回空，**却没有任何一行说为什么**。

   建完照 W4 收尾：把这件事落进 **L3**（用 `dangan_weave pattern:'落档'`，带 `commit:true`；骨架里的 `T1` / `E1` 是**示例行**，贴完格式要删掉）。

**建出来的骨架**（这就是"档案"的全部定义，活在内置骨架里，不在任何一份用户数据里）：

```
<档案根>/
├── 从这开始读.txt                    ← 入口：七层结构 + 读序
├── L1-必读/  总览 · 铁律 · 使用说明（W 判据）· 工具速查 · 索引 · 防丢失总则 · _说明-读我 · 用户

```

- 🔴 **只补缺、绝不覆盖**：目标文件已存在就**跳过并报出来**，绝不清空、绝不改名。

  ③ **馆表里的「活跃馆」**（`~/.dsh/memoria/memoria-archives.json` 的 `active` —— 2026-10-16 加，随包脚本没配置可读时用它）

## 四、安装

只走官方入口 —— 一条命令做全三件事（**link 进 profile 的 `node_modules`** + dependencies + **`dsh.profile.bundles`**）：

```powershell
dsh plugin --profile web add <本目录的绝对路径>
```

> ⚠️ **漏掉 `bundles` 那一步的插件永远不会被加载**，而且**不会报错**（自己手动放 junction 最容易漏这一步）。

## 六、怎么确认它在跑

它**坏掉是静默的**（插件可以从组合树里悄悄掉出去，不报错、不告警）。所以有**四道**自证：

1. **`~/.dsh/memoria/memoria.log`** —— 每次 `apply` 都记：**版本与代码指纹**（指纹变没变＝这次重启到底换上新代码没有）、入口读没读到、铁律找到没、**哨兵各自读到几条**（⚠️ 现在只剩**作废哨兵** —— 等级哨兵随 L2 于 2026-10-15 退役删除；**哨兵必须自报工作量，否则"没出声"分不清是"没问题"还是"它瞎了"**）、哪个工具注册了。
2. **在岗标记** —— 每个新会话首轮会注入一行极短的 `〔梅莫莉亚在岗 <时间>〕`。**它消失了 = 它没在跑。**
3. **`~/.dsh/memoria/memoria-gate.log`** —— 落档闸门每次判定都记一行（通过 / 本该拦 / 已拦 / 豁免）。
4. **`[干活统计]` 行**（2026-09-17 · 0.10.0）—— 回合结束时，闸门日志里多一行形如
   `[干活统计] F1=3(注入 17955 字符) F5=2(0 错)`：**每个能力只在有变化时写一次**（不重复刷屏）。
   📌 **判据：`hook` 型能力若整场日志里从没出现过它 → 装了等于没装。**
   ⚠️ 它**不记"没动过"** —— 没动 ≠ 出错，但"整行里没有 F1"本身就是证据。

> ⚠️ **`~/.dsh/memoria/memoria-pending.json`**：压缩落地后"等着补一次完整注入"的**落盘置位**。
> 为什么落盘：它原来只在内存里，而"压缩 + 重启"会把内存抹掉 —— 2026-09-16 深夜实测，那次 17,955 字符的重注入**一次都没发生**（记在档案 `A19`）。

## 七、设计原则（改代码前先读这一节）

1. **对档案默认只读；写入是例外。** 平时她只**看护**档案（体检 / 提醒 / 拦住漏落档）；**唯一的写入口是"落笔半"**，而且它**只走「改档工具」那扇唯一的门**，不自己另开一条写档案的路。欠账、状态、日志一律写 `~/.dsh/`，**绝不在档案里拉屎**。（2026-09-16 深夜按用户要求改口：原来是"一个字都不写"。）
2. **零运行时依赖、免构建。** 不 `import` 任何 `@deepseek-ai/*` 包；需要的那条 user 消息**手写**即可（宿主包在 Junction 布局下按 realpath 解析会找不到，隔壁 `meow-memory` 因此必须 esbuild 打包）。
3. **全程 fail-open。** `pre-step` 是 async 监听器，本插件抛错会沿 agent-loop 传播、改变宿主 turn 的错误语义——**所有自己的逻辑一律 try/catch 吞掉并放行**。
4. **注入消息必须打 `source.kind='plugin'`**，否则会被当成真实用户消息。
5. **门由机器算，不由我自报。** 闸门的判据是**档案的物理状态**（T/E 计数 + 机械体检），我说"完成了"不起任何作用。
6. **闸门有界、且让位于用户。** 同一会话连续拦 3 次就放行并记欠账（防死循环）；最后一条真实用户消息里出现"先别记／不用了／就这样"就放行并留痕。

## 十二、模块化接口（2026-09-16 深夜定 —— 用户提出"梅莫莉亚需要模块化"）

> 用户原话："**现在我们做的很多事情都是在给梅莫莉亚加功能，如果没有一个很好的接口的话，后续每次添加都会麻烦。**"
> 参考对象：`Phant0Meow/dsh-meow-memory`（**一个能力一个模块**：db / bm25 / inject / dream / reflect / tools / apply；**文案放数据文件**；**配置声明成 schema**）。

**加一个功能 = 加一个文件 + 在清单里加一行。** 四层各管各的，不许越界：

| 层 | 是什么 | 规矩 |
|---|---|---|
| `lib/<代号>-<名字>.js` | **能力内核**（纯逻辑 ＋ `register<X>(ctx)` / `report<X>()`） | 只 import `common.js`；不认识别的能力、不认识 CLI |
| `lib/tools.js` | **给模型看的门面**：ToolDefinition（参数校验 + 包装内核） | 内核不写在这里 |
| **`lib/manifest.js`** | **能力清单＝装配的唯一来源**（0.7.0 起）：每项写清 `id / title / kind / what / register 或 tool / selfCheck` | **加功能＝加一个文件＋这张表加一行**；`index.js` 一个字都不用改 |
| `lib/index.js` | **照清单装**（0.7.0 起）：遍历清单 → 挂事件 / 注册工具 / 跑自检 | 只做装配与日志，不写业务 |
| 自检 | 每个能力**启动时自报工作量**（"读到几行""内核在不在"） | **沉默 ≠ 正常**：必须能区分"没问题"和"它瞎了"（R26 的教训） |

**清单自己会体检**：`manifestProblems()` 在启动时查三件 —— **代号不许重复**（撞号＝两件事共用一个名字，与"两个真 R5"同一个坑）· 每项必须能被装（有 `register` / `tool` / `selfCheck` 至少一样，否则"装了等于没装"）· `id`/`title` 不许缺。
**给面板留的口子**：`capabilityList()` 是不含函数的纯数据版（`{id,title,kind,what}`），将来控制台面板直接读它，不必反向解析代码。

**还要补的两件（学 meow-memory）**：① **文案外置**（注入的协议文本与中文说明放数据文件，改文案不必碰代码）；② **配置声明化**（写成 schema → DSH 设置页能图形化改、字段级保存）。~~③ 能力清单~~ ✅ **0.7.0 已做**。
