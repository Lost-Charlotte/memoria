# assets —— 她的形象图

| 文件 | 是什么 | 界面里用在哪 |
|---|---|---|
| `memoria-idle.webp` | 待机（手交叠、笔记本合上） | 平时 |
| `memoria-busy.webp` | 工作中（动笔写） | 鼠标悬停时 |
| `memoria-show.webp` | 展示面板（举起笔记本） | 面板展开时 |
| `memoria-sheet.webp` | 三视图（设定参考） | 界面里没用到（备用） |

**规格**：**原生 848×1264**（不缩），带透明通道的 **WebP q88**，每张约 **108–114 KB**。
⚠️ **不缩尺寸是有原因的**：界面支持**滚轮缩放**（60%–250%），100% 时她只有 168px 宽 —— 缩到 250%（420px）时
**在 2x 屏上仍是 1:1**，再往上才会糊。所以**别把这批图缩小**，缩了就白缩。

同一张图三种格式实测（`-Width 848`）：

| 格式 | 体积 | 说明 |
|---|---|---|
| PNG（32bpp ARGB） | 1.11 MB | 中间产物，不发布 |
| WebP 无损 | 530 KB | 没必要 |
| **WebP q88** | **108 KB** | **采用**（这个尺寸下看不出差别；alpha 由 libwebp 无损保存） |

**来历**：桌面 `梅莫莉亚形象库\` 的 4 张 **848×1264 PNG（纯白底、无 alpha）** → 抠底 → 转 WebP。

**为什么要抠底**：**白是她的主色**（白衬衫、白袜、发丝高光）—— 全局色键一抠就把她抠掉一块；CSS `mix-blend-mode` 也不行（悬浮窗是 `position:fixed` ＋ `z-index`，自身成了**孤立组**，混合看不见网页背景）。所以只吃掉**与图片四边连通的白**，她身上的白全部保留。

**怎么重建**（换了原图之后照这个跑；一张一张来）：

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\make-assets.ps1 `
  -Src "<形象库>\梅莫莉亚待机.png" -Dst assets\memoria-idle.webp `
  -Width 848 -Dilate 6 -DropRect 110,262,362,312 `
  -Ffmpeg "<工具箱>\04-图片与媒体\ffmpeg\bin\ffmpeg.exe"
```

- `-Dst` 以 `.webp` 结尾时：脚本先把抠好的 PNG 写到 `%TEMP%`，再用 ffmpeg 转 WebP，转完删掉那个临时 PNG（只删它自己刚建的那个）。
- `-DropRect x0,y0,x1,y1` ＝ 额外清掉的矩形，用来抹掉**烤进图里的字**（**按原图 848×1264 的坐标**）。
  只有**待机图**有那行 `[SYSTEM: IDLE / AWAITING INPUT]`（在 `110,262`–`362,312`，那块本来就是白底），另两张不用给。
- `-BgMin 240`（默认）＝ 认"背景白"的阈值；`-Dilate 6` ＝ 颜色向外渗几圈（防缩图白晕）。
- ⚠️ **`-Ffmpeg` 要给全路径**（本机 ffmpeg 不在 PATH 上）；**脚本本身必须保持纯 ASCII** —— PS 5.1 按 ANSI 读 `.ps1`，中文路径字面量会把脚本读崩（已经踩过一次）。
- 产物会打印一行统计（抠掉多少、解白多少圈、webp 多少字节），**看着不对就先在单张上试**。
